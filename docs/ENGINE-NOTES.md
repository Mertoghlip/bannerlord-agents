# Engine notes: Bannerlord 1.4.8 + TAOM 2.0.26

What the game and the TAOM pack do, as read in their code and seen in play while building the agents. Verified on my laptop (the Legion); the decompiled source and the tools named here live on it, outside this repository.

- Decompiled 1.4.8 source: `C:\BannerlordArchive\refsrc\TW148` (laptop only). `C:\BannerlordArchive\tools\RefCheck` lists every game member a DLL references that no longer exists.
- Movement commands are on `MobileParty`, not `MobilePartyAi`: `SetMoveGoToSettlement(s, NavigationType, isTargetingPort)`, `SetMoveGoToPoint(CampaignVec2, NavigationType)`, `SetMoveEngageParty`, `SetMoveGoAroundParty`, `SetMoveEscortParty`, `SetMoveBesiegeSettlement`, `SetMoveRaidSettlement`, `SetMoveDefendSettlement`, `SetMovePatrolAroundSettlement` / `SetMovePatrolAroundPoint`, `SetMoveModeHold`. Stop the stock AI for a party with `party.Ai.SetDoNotMakeNewDecisions(true)`. `SetInitiative(attack, avoid, hours)` also exists.
- Visibility is computed only for the player (`PartyBase.UpdateVisibilityAndInspected`). Faction views are ours to compute: each observer's `MobileParty.SeeingRange` against `Campaign.Current.Models.MapVisibilityModel.GetPartySpottingRatioForMainPartySeeingRange(target)`.
- Diplomacy: `DeclareWarAction`, `MakePeaceAction`. Alliances and calls to war are kingdom decisions (`StartAllianceDecision`, `ProposeCallToWarAgreementDecision`, `AcceptCallToWarAgreementDecision`) backed by `AllianceCampaignBehavior` / `AllianceModel`.
- Clock: `Campaign.Current.TimeControlMode` and `Campaign.Current.SetTimeControlModeLock(bool)` (not used for agents: the clock never stops).
- A frozen party still takes the initiative against an enemy that is in a map event at, or besieging, its target settlement (`MobilePartyAi`, around line 486). This is expected behaviour, not disobedience.
- Events used: `HourlyTickEvent`, `TickEvent`, `OnBeforeSaveEvent`, `OnSaveOverEvent(bool, string)`, `OnGameLoadFinishedEvent`, `MapEventStarted(MapEvent, PartyBase, PartyBase)`, `OnSiegeEventStartedEvent(SiegeEvent)`, `ArmyCreated(Army)`.
- Player visibility: `PartyBase.UpdateVisibilityAndInspected` → `CalculateVisibilityAndInspected` compares the distance against `MapVisibilityModel.GetPartySpottingRatioForMainPartySeeingRange(target)`. The faction-view rule must reproduce this exactly for the main party; that is the recorder's vision check.
- Party AI Controls (installed 1.4.5; decompile of the same names at `C:\BannerlordArchive\refsrc\PAI`) holds vassal and clan-party orders. The static `PartyAIControls.SubModule.PartySettingsManager` is a `PartyAIClanPartySettingsManager`. A lord's current order is `settings.Order`: a `PartyAIControls.PAICustomOrder` with a target and a nested `OrderType` (DefendSettlement, PatrolAroundPoint, PatrolClanLands, StayInSettlement, RecruitFromTemplate) plus `Text`. **Never call `Settings(Hero)` from this project except in `PacLink`:** for a lord without an entry it ADDS one to `_partySettings` (PartyAIClanPartySettingsManager.cs ~371–404), and `_partySettings` is saved with the game (`SyncData`, ~566). Read the internal `HeroesWithOrders` list (~207) or the `_partySettings` dictionary instead. `PacLink` (0.11.1, the lieutenant) does make entries, for the ruler's realm's lords only: the ones made just for a mirror, the mirrors themselves and the vassals put on TFAOMFixes' `VassalOrders.Commanded` for them are taken out before every save and put back after; what `party_ai` sets stays, as Party AI Controls' own state. The decompile at refsrc\PAI is OLDER than the installed 1.4.5 (no `RecruitFromEnemySettlements`, no `SetPartyTemplate`, `DismissUnwantedTroops` default true there, false installed): decompile the installed `Modules\PartyAIControls\bin\Win64_Shipping_Client\PartyAIUpdated.dll` (`ilspycmd -p`) before relying on a member.
- Hardware: Core Ultra 9 275HX = 8 P-cores + 16 E-cores (24 threads); RTX 5090 Laptop, 24 GB. In big battles the main thread runs at ~90% of a core, the process uses ~15% of all cores, and the GPU is 21–41% busy. The campaign map has not been measured yet. A TAOM 2.0.26 campaign has about 3,350 parties.
- Harmony, if needed: `new Harmony(id).PatchAll(typeof(SubModule).Assembly)`. A bare `PatchAll()` throws under BLSE and hides the crash window, which looks like a black-screen boot stall. Use the Harmony 2.4.2 that TAOM.Dependencies bundles.
- TAOM.Dependencies' PatchShield silently REMOVES every foreign patch on a method once any patch on it throws MissingMethod, MissingField or TypeLoad. Log which patches are really in place at session launch.
- Patches on tiny getters get bypassed because callers inline them: patch the caller. TAOM wraps many game models: patch the runtime model's public method (`Campaign.Current.Models.X.GetType()`), not a default model's private worker. Never scale a saved value inside a getter, because it compounds every session.
- Logs to read: `C:\ProgramData\Mount and Blade II Bannerlord\logs\rgl_log_<pid>.txt` (engine) and the TAOM crash bundles in `<game>\bin\Win64_Shipping_Client\logs\taom_crash_*.zip` (read report.txt first).
- Any change to the enabled module list costs one slow load while the shaders rebuild.
- **When things tick (1.4.8, verified Oct 8).** `Campaign.Tick` fires `CampaignEvents.TickEvent` and the periodic (hourly) events only while `_dt > 0`: not while paused, not in a town menu unless waiting, and not in a battle (MapState does not tick then). So `Background.ToMain` (agent orders) waits for the clock; the agent gets a RECEIVED receipt meanwhile. `MBSubModuleBase.OnApplicationTick` runs every frame in every state (the heartbeat).
- **A second thread touches parties.** `MapScreen.OnPostFrameTick` invokes `Campaign.CampaignLateAITickTask` (`Campaign.LateAITick` → `PartiesThink` → every party's `MobilePartyAi.Tick`) as an async task; `Campaign.RealTick` waits for it at the start of the next frame. So campaign event handlers are safe, but `OnApplicationTick` can overlap it: read no party state there. Hooks on movement code may run on that thread.
- **Every movement command** (`MobileParty.SetMove*`) starts with the private `MobileParty.ResetAllMovementParameters()` (~55 bytes of IL, not inlined): the one door for watching plan changes.
- **Armies and held lords (read in the 1.4.8 source for 0.4; not yet all seen in a game):** a party with `DoNotMakeNewDecisions` also loses its quick reactions (no fleeing), so every tool carries our own safety rule. Besiegers assault by themselves once their siege engines are ready. `Kingdom.CreateArmy(leader, gatheringPoint, type, members)` charges the clan influence per member in `Army.OnAddPartyInternal` (price from `ArmyManagementCalculationModel.CalculatePartyInfluenceCost`); members march to the leader through the AI's escort behaviour; the army disbands after about 48 idle hours, on cohesion 0, when over half its parties starve, or with no war. A mercenary clan's lord cannot lead; the ruler cannot be called as a member. Setting `army.AiBehaviorObject` keeps the gathering point the agent named; `CreateArmy` fires `ArmyCreated` before that, so the notice takes the place from `Orders.FormingAt`. Seen in the game (Oct 9): armies form at once and called lords follow (EscortParty). A tool's first step judges the world from the hour's copy, taken before its own order acted: anything the order itself changes (an army) is judged from the next hour (gather's false "broke up before it formed", 0.5.0).
- **The game's own history (`Campaign.Current.LogEntryHistory.GameActionLogs`, read for 0.5):** entries are deleted after `KeepInHistoryTime`, 7 days by default (a peace 40 days, a capture 84, alliances and calls to war 4 years, a death never). `IEncyclopediaLog.GetEncyclopediaText()` is the game's sentence with encyclopedia links (`<a ...><b>Name</b></a>`): strip the tags. `ChangeSettlementOwnerLogEntry.IsVisibleInEncyclopediaPageOf` is false for a change by siege (`SiegeAftermathLogEntry` covers it), so read its `PreviousClan`/`NewClan` fields instead. New events used: `OnSiegeEventEndedEvent`, `HeroKilledEvent`, `HeroPrisonerReleased` (with `EndCaptivityDetail`, namespace `TaleWorlds.CampaignSystem.Actions`).
- **Sieges and relief (read in 1.4.8 for 0.6):** a party attacking a besieger starts a `SiegeOutside` battle (`StartBattleAction.Apply`; `MapEvent.Initialize` leaves `MapEventSettlement` null there, so `AddInsideSettlementParties` does not run); all besieging parties join the defending side. The garrison and the lords inside join only through `SallyOutsCampaignBehavior`: on `MapEventStarted` and every settlement hour, when (inside strength for `SallyOut` + friendly parties near the camp, aggressiveness-weighted) > 1.5 x (enemy parties near the camp), they are put on the relief's side (the event becomes `SallyOut`). Without a relief the bar is 2x, checked when the hour is divisible by 4. `Town.GetDefenderParties(SallyOut)` leaves militia out. TAOM does not touch any of it.
- **Where volunteers are (read Oct 29, 0.13.3):** the base game gives notables to towns (2 merchants, 2 gang leaders, 1 artisan) and villages (1 headman, 2 rural notables) only (`DefaultNotableSpawnModel`); TAOM keeps those counts, some peoples' feats changing them (`TaomNotableSpawnModel`), and adds castle recruiting (`TAOM.Features.CastleRecruitment`: 3 notables a castle by default, gang leader, headman, merchant; its AI switch on by default, so the game's lords recruit there too). Each notable holds 6 volunteers (`Hero.VolunteerTypes`). In our records castles gave the most men in all (147k of 268k), towns the most a visit (about 10 against 6). `RecruitTour.MayRecruitHere` takes any place with notables; since 0.13.4 `Recruitment`'s day log counts castles too (volunteers waiting, and hours where a lord could recruit), and defend takes its own castle's volunteers before riding to a town or village.
- **Recruiting (1.4.8, `RecruitmentCampaignBehavior`):** lords the game runs recruit in `HourlyTickParty` only while at a town (not besieged) or unraided village, held lords included (it does not check `DoNotMakeNewDecisions`); gates: `PartyTradeGold > HeroHelper.StartRecruitingMoneyLimit` (50 + 20 x min(150, men)), non-leaders also `Clan.Gold > StartRecruitingMoneyLimitForClanLeader` (50 + leader party wages + 40 x leader party men), room below the size limit, not starving, `GetAvailableWageBudget()` per recruit, notable slots below `VolunteerModel.MaximumIndexHeroCanRecruitFromHero`. `Clan.Gold` is the leader's gold.
- **Patrol and held lords (1.4.8, read for 0.6.1):** the game's patrol (`PatrolAroundPoint`, `GetLandPatrolBehavior`) walks to random reachable points in a ring between 0.5r and r from the gate, r = `FortificationPatrolDistanceAsDays` (0.5) or `VillagePatrolDistanceAsDays` (0.25) x 24 x the party's own speed: 20 to 41 map units from a castle at the orcs' median speed of 3.4. TAOM does not change it. So tools with a `radius` (defend, screen) patrol with our own `SetMoveGoToPoint` points instead (`Orders.NextPatrolPoint`). A held party (`DoNotMakeNewDecisions`) skips the initiative step (no chase, no flight) except against an enemy in a battle at, or besieging, its own `TargetSettlement` (`MobilePartyAi.GetBehaviors`, line 486). An AI party sent into a besieged friendly town or castle simply enters at the gate (`EncounterManager.StartSettlementEncounter`), and once inside it cannot be called out (it is part of the defence).
- **Would a place hold (1.4.8, read for 0.6.2):** besiegers assault only when `StartingAssaultOnBesiegedSettlementIsLogical` (BesiegerCamp): besieger strength > defenders' `CalculateCurrentStrength` (every party inside: garrison, militia, lords) x advantage^k, advantage = `GetSettlementAdvantage` = (1 + 4 + (wall level - 1)) / (1 + engine bonuses: +0.25 ram or tower, +0.16 ram or +0.24 improved ram, +0.16 one tower or +0.24 two, +0.08 per trebuchet/onager/ballista, +0.12 per fire engine), a quarter of the walls' part once they are breached; k = 0.8 (x1.25 without a ram, x1.25 without a tower), falling 0.02 an hour after 4 days. `World.WallFactor` takes a ram and two towers built (2.4 / 2.8 / 3.2 for wall levels 1 / 2 / 3). Wall level: `Town.GetWallLevel()` (fortifications building level). Militia: `Settlement.MilitiaPartyComponent.MobileParty`. A party in a settlement leaves by itself once its short-term target is elsewhere (`CheckExitingSettlementParallel`), unless it holds. Above the bar the assault is a roll each check (ratio x engines built/3 x a progress factor x 0.1), so stronger besiegers storm sooner; k reaches 0 about 136 h into a siege and goes negative after, so a long siege storms even below the defenders' bare strength. A player leading the siege is not bound by this test.
- **Party AI Controls wakes held lords (read for 0.6.3):** `PartyAIThinker.OnHourlyTickParty` (~150 in the decompile) switches `DoNotMakeNewDecisions` back off for every lord party it does not manage (`IsHeroManageable` false: not the player's clan, nor the player's kingdom's when it manages those) whose `DefaultBehavior == Hold` (0 in 1.4.8's enum: Hold, None, GoToSettlement, ...). Every held lord standing still (a gather leader waiting, a lord arrived at a village) was released this way each hour, and the game's hourly decision (`AiPartyThinkBehavior.PartyHourlyAiTick` runs only while the flag is off) moved it before our hourly re-issue. The game itself puts parties into Hold in ~36 places (battle ends, settlement entry, armies), so avoiding Hold in our own moves is not enough: `GameHooks.KeepHeldPatch` (prefix/postfix on that method, first argument by position) holds again a lord one of our orders holds. Nothing in the base game turns the flag off for a lord (only quests' own parties and `TeleportHeroAction`); Improved Garrisons only its own parties. Self-check "held lords kept held" fails when Party AI Controls is loaded and the hook did not attach.
- **Found after run C1 (Oct 23, 0.11.3):**
  - **Villages:** a lord the game runs steps into a village and straight back out, left standing at it (`EncounterManager.StartSettlementEncounter`'s last step: `LeaveSettlementAction` + `SetMoveModeHold`), so `CurrentSettlement` is null there. Use the game's own test, `MobilePartyHelper.GetCurrentSettlementOfMobilePartyForAICalculation` (its `LastVisitedSettlement` within 1), as `Orders.Where`/`At` do. Before, every village stop looked like "not arrived", and recruit trips bought at 2 of 1,562 village stops.
  - **A battle's end:** `MapEventEnded` fires after `CaptureDefeatedPartyMembers` has taken the losing lords from their parties (`LeaderHero` null; the parties stay in the side's list until `HandleMapEventEnd`). Count a side's lords at `MapEventStarted`, or from `MapEventParty.Troops`/`WoundedInBattle`/`DiedInBattle`.
  - **The player's clan is fixed:** `Clan.PlayerClan` is the clan `player_faction` (`Campaign.PlayerDefaultFaction`), whoever the player plays. With it ruling, a due vote waits for the player (`KingdomDecision.NeedsPlayerResolution`), and the map opens the kingdom screen for it only when no menu is up. `Votes` settles them as for a computer-run realm (`KingdomElection.StartElectionWithoutPlayer`) while the player is not the ruler. The game puts one holding's vote at a time, and a taken holding goes to the ruler's clan until then.
  - **TFAOMFixes' recruiting trip** (`LordRecruiting`): a computer lord below 50% ranks, not in the player's clan nor managed by Party AI Controls, is steered with the game's AI off to 80%. It waits while another switched the AI off, and takes him the hour after our order ends. It drops him only when our order's place differs from its own: `LordTours.Drop` takes him off it when any order of ours starts.
  - **Prisoners handed over** (`SellPrisonersAction`, what a computer lord does on entering a friendly castle or town): soldiers are sold. An enemy lord handed to one's own realm's holding goes to its dungeon as a gift that earns the realm influence (`InfluenceGainCampaignBehavior`), and then the game pays for none of that hand-over, its soldiers included; they are taken, not kept. That is the game's rule for every lord (Oct 23: lords can sometimes place prisoners in the dungeon instead of selling them), so `Purse.CashIn` makes one hand-over as the game does; the record names it "prisoners given to a dungeon" (C1 had 27, all this rule).
  - **Hired clans** leaving a realm take their gold out of a realm's sum (five left the orcs in C1, 8.9M): the scoreboard keeps `hired_gold`.
- **Found in run C2 (Oct 23, 0.11.4):**
  - **The game's own sally** (`SallyOutsCampaignBehavior.CheckSallyOut(Settlement settlement, bool checkForNavalSallyOut, out bool salliedOut)`, private): every 4th in-game hour (`floor(hours) % 4 == 0`, from the settlement's hourly tick), and beside a relief's battle at the camp. Everyone inside (`GetInvolvedPartiesForEventType(SallyOut)`, strength as attacker in a plain battle) plus friendly parties within `GetEncounterJoiningRadius` (3) of the camp's leader go out when more than 2 times the enemy parties there not in a settlement, weighted by `Aggressiveness` (full above 0.5). Beside a relief: 1.5 times, and they join its battle. It starts the battle with the garrison as leader (`EncounterManager.StartPartyEncounter(GarrisonParty, leader)`), and the whole besieging army fights it in the open. Skipped when the player leads the defence from inside. No installed mod touches it. In C2 it sent Aragorn's and Imák's sheltering armies (5,938 men, 20 lords) out against Lorgath's 22.6k the hour his siege began: all lost. By our numbers it needed under 8k of Lorgath counted; why it counted so little is not known yet. 0.11.4's `SallyGate` keeps the defenders inside while one of our ordered lords is there, and records the game's numbers ("sally" events).
  - **At war:** `FactionManager.IsAtWarAgainstFaction` asks the diplomacy model first (TAOM's War of the Ring table, which TFAOMFixes `RingWars` fills for the player's realm), then the stance. `StanceLink.IsAtWar` alone says peace for the shadow's realms the player's realm was never declared on (Dol Guldur). TFAOMFixes fills the table at session start just after this mod, so check wars from the first hour, not at the load.
  - **A channel's mode:** `AgentChannel.ModeText()` (static) is the first agent's (`Primary`); a channel's own is its instance `ModeText()`. 0.11.3 and before headed every agent's poke and report with the first agent's mode, so in C2 the kingdom's live agent read "SHADOW ... none is carried out" (B too, where the orcs, listed first, are in shadow).
- **Army counts:** `Army.TotalHealthyMembers` and `EstimatedStrength` count the leader and ATTACHED parties only; a called lord still marching counts on its own. `MaximumDistanceToCallToArmy` = average distance between neighbouring towns x 8 (a cached lookup); the influence price rises with distance. `Army.Gather` with no members is fine (an army of its leader alone); inactivity (48 h) counts Hold, PatrolAroundPoint and GoToSettlement to a friendly place, not GoToPoint.
- **The AI's decision step:** `AiPartyThinkBehavior.PartyHourlyAiTick(MobileParty mobileParty)`, a listener of `TickPartialHourlyAiEvent` (tickers built with doParallel false: main thread). It returns at once if `Ai.DoNotMakeNewDecisions`; thinks every 1, 3 or 6 hours (`Ai.HourCounter`, reset to 0 then incremented, so 1 after a think); resets `mobileParty.ThinkParamsCache`, fires `AiHourlyTickEvent` for the behaviours to add `(AIBehaviorData, score)` pairs, picks the best; moves to it only if `MBRandom.RandomFloat < best` (up to N rolls) and best > a bar (0.03 for patrol/visit, else 0.1; x2 when gathering an army, x0.33 for an army leader), or always when holding with a score over 0.01. Gathering an army calls `Kingdom.CreateArmy`.
- **Ways and the walking map (read in 1.4.8 for 0.7, docs/ROUTES.md):** `MobileParty.ComputePath` asks `MapSceneWrapper.GetPathBetweenAIFaces(CurrentNavigationFace, target.Face, ..., agentRadius 0.3, Path, invalid face groups, extraCostMultiplier 2f, region switch costs)`: the shortest way over walkable faces (what the multiplier applies to is in the engine; the dashboard's accuracy check weighs three guesses). `Path` is a public `NavigationPath` (128 corners, `Size`); the party walks `Path[PathBegin]` onward while the private `_pathMode` is on (`DoAiPathMode`), else straight at its target; it plans again when its target moves. The cached final speed is the internal `_lastCalculatedSpeed`; `LastCalculatedBaseSpeed` is the base. Walkable for land (`DefaultPartyNavigationModel`): plain, desert, snow, forest, steppe, swamp, dune, bridge, fording, beach (farmland `RuralArea` is not); no naval in the default model. Speed (`DefaultPartySpeedCalculatingModel.CalculateFinalSpeed`): forest −30%, water/river/bridge/ford −30%, desert/dune −10%, snowfall −10%, night −25% (night = outside `CampaignTime.SunRise`..`SunSet`, 2..22 by default). The face group index is the `TerrainType`. Map queries (`IMapScene`): `GetMapBorders`, `GetSceneNavigationMeshCrc` (the map's key), `GetNumberOfNavigationMeshFaces`, `GetFaceAtIndex`, `GetNavigationMeshCenterPosition(int)`, `GetFaceIndex(in CampaignVec2)`, `GetTerrainHeightAndNormal`; the game calls `GetFaceIndex` from its parallel party code, so the export may ask from `OnApplicationTick`. `Settlement.GatePosition` is where parties march to.
- **Road distances, watch and shadow (0.7.1, 2026-10-16):** every distance the agent reads is given as the crow flies and by road ("63.0 (260.0 by road)"), the road figure being the game's own: its navigation cache holds the real way between every two holdings' gates (filled for all pairs at campaign start or read from the pack's `ModuleData/DistanceCaches/settlements_distance_cache_Default.bin`, so `MapDistanceModel.GetDistance(Settlement, Settlement, ...)` is a lookup; a pair missing would be searched and cached by the game), copied at load into `RoadBook` (`Capture.RoadsFor`: the two followed realms' holdings to all, each holding to its 12 nearest); from a party, through `GetClosestEntranceToFace(CurrentNavigationFace)` (copied hourly as `PartyRow.Entrance`), as `DefaultMapDistanceModel.GetDistance(MobileParty, Settlement)` does. The game's own party-to-party distance is only the straight line; ours goes entrance to entrance. Spots (`p673_994`) name points on the map for the `watch` order (`post` move); `shadow` re-works its point every hour. A rule's `set` runs before its call-back text is filled: a call-back must not name a value its own rule clears.
- **Siege timing and army pace (read in 1.4.8 for 0.7.2, after Hollin Gate; docs/TOOLS.md):** an AI besieger storms only via `MobilePartyAi.GetBesiegeBehavior` when `BesiegerCamp.IsReadyToBesiege`: `IsPreparationComplete` (the `preparations` engine, 48 man-days in Native's `siegeengines.xml`, built at `GetConstructionProgressPerHour` = √(healthy men) man-days a day: ~26 h for 2,000 men), then at least one engine built (`GetNumberOfEquipmentsBuilt` > 0, else the score is multiplied by 0; ram 12 man-days, ballista 8; engines start only after preparations, `DefaultSiegeStrategyActionModel` line ~151), then a random roll each check (`StartingAssaultOnBesiegedSettlementIsLogical`). The siege camp's work runs in `SiegeEvent`, untouched by `DoNotMakeNewDecisions`. A party's land pace is `4 × (200/(200+men))^0.4` with ALL attached parties' men, wounded, prisoners, herds and cargo pooled on the army leader (`CalculateLandBaseSpeed`); the attached parties' own speeds in our rows mean nothing. The besieged realm's AI sends free lords to the holding one by one (DefendSettlement), and each joins a storm already under way: the relief alarm counts lords, not armies (`World.ReliefComing`). The game clock never stops while the agent thinks (PLAN.md): about 1 in-game hour per 3.5 real seconds at the speed I play.
- **The game's clocks (0.7.3, 2026-10-17, docs/TOOLS.md "The game's clocks"):** a party covers **speed / 1.2 map units an in-game hour** (`Campaign.Tick`: 4,320 s of map time per dt; measured 0.81 on Oct 16's frames); the speed is base x (1 + one sum of factors), the ground and night ADDED into it (not multiplied), at least 1; the active speed model is TAOM's `TaomPartySpeedModel` (vanilla final speed + peoples' ground/night feats + hero career passives). Read the base parts from `MobileParty._lastCalculatedBaseSpeedExplained` (the game's own cache, no new sum) and measure the rest from `_lastCalculatedSpeed` each hour (`GamePace.Residual`; on Oct 16 about +0.19 per lord, likely Uncanny Insight from boosted Scouting): never multiply 0.7/0.75 factors again. Several mods adding one model: the last registered wins (`GameModelsManager.GetGameModel` scans from the end). Siege: `GetConstructionProgressPerHour` via the model in force (Cheats' postfix neutral at its settings), storm rolls ~3.08/h by the camp leader's AI, `StartingAssaultOnBesiegedSettlementIsLogical` formula in `Forecast.Siege`; hunger wounds 10% of the garrison a day, never surrender. Battle: storm 1 round/h, others 2; strikes by `GetSimulationTicksForBattleRound` (never call it between rounds: the pool is empty then); TAOM's combat and power models. `Dashboard etacheck` checks the marching rule against real arrivals (Oct 16: 2.5% median error on marches of 12 h+, against 8.8% for distance/speed).
- **Moves in a battle, arrivals, raids (0.7.5, docs/TOOLS.md "What the first evening on 0.7.4 taught"):** a `SetMove*` given to a party in a `MapEvent` is taken but the party moves only once the battle ends (tools test `in_battle`). A lord's `MoveTargetPoint` (Tx, Ty) is often a waypoint short of the holding it heads for (a DefendSettlement lord walked straight to a point 8.6 ahead, 96.5 by road from the castle; a released lord to a point 7 ahead of a 488-long march): time an arrival along the way only when it ends within 5 of the holding or its gate. A raid with no defenders loots the village when `SettlementHitPoints` reaches 0, taking (sqrt(raiders) + 5) / 900 an hour (`RaidEventComponent.Update`, `DefaultRaidModel.CalculateHitDamage`; TAOM's `TaomRaidModel` adds feats and career passives). Battle simulation (`MapEvent.SimulateBattleRound`, `DefaultCombatSimulationModel`): a round every 60 minutes in a storm, 30 otherwise; each strike's damage (0.5 to 1) x 40 x (power ratio)^0.7 x advantage x morale factor knocks the troop down when a random number below its MaxHitPoints (100 for troops) is under it. The Hollin Gate storm ran at about 40% of the rules' expected defender blows and 150% of the attacker blows (power 1.57 against 1.93 by the model), so battles under way are run ahead at measured rates.
- **A holding's gate is not its centre (0.12.1, docs/TOOLS.md "Arriving at a castle"):** `Settlement.GatePosition` lies a median 2.9 from a castle's `Position` and 3.3 from a town's (up to 7.1; villages 0). A lord sent close to a holding stands by its gate, so every "has he arrived" test measures to the nearer of the two (`World.Near`); measured from the centre, three sieges stood 6.2 to 7.8 off for up to 15 days in run 20261025-1524-C2.
- **The one door to an AI storm (0.7.4, docs/TOOLS.md "Siege control"):** `MobilePartyAi.GetBesiegeBehavior` turns the camp leader to `AssaultSettlement` only when `BesiegerCamp.IsReadyToBesiege` holds: `IsPreparationComplete` and then the private `StartingAssaultOnBesiegedSettlementIsLogical()` (not inlined; the defenders inside not shy of a fight, militia and garrison, halved with the player inside, against every camp party's `CalculateCurrentStrength`, then the ram/tower terms). So a prefix on it decides every AI storm and is never asked before the preparations are done; the player's own storm menu does not go through it. Storming needs no engine built: the player may storm the moment the preparations are done.
